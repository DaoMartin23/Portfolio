F1 Strategy Sim

Browser-based F1 race strategy game. Pick a car and grid slot, race a 20-car field lap by lap, and make the calls when it rains, when a safety car comes out, when to pit.

  • Python
  • FastAPI
  • React
  • TypeScript
  • Monte Carlo
View repo

Overview

You are the strategist, not the driver. Choose a car and a starting position, then run the race one lap at a time against nineteen AI-controlled rivals. Tyres degrade, weather turns, safety cars bunch the field, cars pick up damage in collisions, and the rivals run strategies of their own. Every one of those is a decision point: stay out, box now, gamble on inters.

The whole race is deterministic. Same seed, same choices, same result. That makes it replayable, debuggable, and, crucially, something you can search over to find the strategy you should have run.

Architecture

Three layers with a hard boundary between each. The simulation knows nothing about HTTP, the API knows nothing about React, and the front end only ever sees JSON.

sim/

Pure Python, no I/O. Every random draw comes from an RNG seeded by (seed, lap, purpose), so lap 23's rain roll is the same whether you replay from the start or resume mid-race.

api/

Stateless FastAPI. The full race state travels with each request and comes back updated. No sessions, no database, trivially horizontally scalable, and every request is reproducible in isolation.

web/

React + Vite + TypeScript. Types are generated from the API schema so the client and server can't disagree about what a lap looks like.

The Monte Carlo optimal-strategy search

After the chequered flag, the debrief screen asks the question every strategist dreads: what should you have done? The answer comes from sampling.

Because the sim is deterministic per (seed, lap, purpose), each candidate strategy is replayed against the exact same race conditions you faced, not a fresh random one. The search runs 500 samples across pit windows and compound sequences, ranks by finishing position and race time, and hands back the best line it found. It takes about 39 seconds, so the front end kicks it off asynchronously and fills the debrief panel in when it lands. You can read your own race summary while it's thinking.

Testing

The sim layer is tested as a pure function: given state and a decision, assert the next state. Determinism itself is under test, so any change that breaks seed-stability fails the suite. The API is tested end to end through the FastAPI test client, and mypy --strict runs across the Python codebase in CI.

pytest -q          # 159 passed
mypy --strict .    # Success: no issues found

What's next

  • FastF1 calibration. Fit tyre degradation and pace deltas to real timing data instead of hand-tuned constants.
  • More tracks. Per-circuit pit loss, overtaking difficulty and weather priors.
  • Reactive rivals. AI cars that respond to your stops rather than running fixed plans.
  • numpy vectorisation. Run the Monte Carlo samples as batched arrays and bring the 39 seconds down to single digits.
