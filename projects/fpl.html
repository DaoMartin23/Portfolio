FPL AI Assistant

Collects Fantasy Premier League and Premier League data from three sources, merges it into one SQLite database, trains a Random Forest model per position to predict each player's points for the next gameweek, and puts a chatbot in front of it.

  • Python
  • scikit-learn
  • SQL
  • LangChain
  • Streamlit
View repo

Overview

Fantasy Premier League is a weekly guess about which footballers will score points. This project replaces some of the guessing with data. A pipeline collects player and club statistics, matches them across sources, and stores them in SQLite. Four Random Forest models, one per position, predict each player's fantasy points for the coming gameweek and write the predictions back into the database. A Streamlit chatbot sits on top so you can ask about players, clubs and predictions in plain English.

Data pipeline

No single source has everything, so the pipeline pulls from three.

FPL API

Season totals, prices, minutes, positions, and each player's gameweek-by-gameweek history.

Understat

xG, xA, shots and key passes, read from an internal JSON endpoint that isn't documented and could change.

football-data.org

League standings, results and fixtures. Needs a free API key and allows one request per 15 seconds per team.

The same player is spelled differently across the three, so a pandas and FuzzyWuzzy step matches names at an 86% similarity threshold before the merge. The result lands in two tables, player_stats and club_stats, linked by club name. build_database.py runs the whole thing end to end.

Goalkeepers, defenders, midfielders and forwards score points under different rules, so each position gets its own RandomForestRegressor with hand-tuned hyperparameters. The features are season totals, the previous gameweek's points and minutes, position-dependent stats such as goals, assists, xG, xA, shots, key passes and goals conceded, and club context like league points and the next opponent. The target is a player's points in their most recent completed gameweek.

Each model is scored on mean squared error and R² against a held-out split of 10 to 30% depending on the position, then saved with joblib into models/.

The chatbot

The Streamlit app routes each question one of two ways. If it matches a fixed keyword list it goes to a LangChain SQL agent, which turns the question into a query against the database and reads the answer back. Anything else goes straight to gpt-4o as a general question. The keyword list is the simplest thing that worked, and it's first in line to be replaced.

Running it

python run.py                  # rebuild the database, then launch the chatbot
python build_database.py       # rebuild only
streamlit run app/chatbot.py   # launch against an existing database

Needs a football-data.org key in .env, a season with at least five finished gameweeks, and fixtures still to play. Rebuilding deletes the existing database.

What's next

  • Cross-validation in place of a single train/test split.
  • An intent classifier to replace the keyword routing.
  • Handling the start and end of a season, when there are fewer than five finished gameweeks or no fixtures left.
  • A stable replacement for the undocumented Understat endpoint.
